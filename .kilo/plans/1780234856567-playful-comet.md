# Frontend Implementation Plan for LMS Angular Application

This plan outlines the frontend implementation needed to consume the backend APIs that were implemented according to IMPLEMENTATION_PLAN.md. The frontend is an Angular application located at ../LMS.

## Important Update on Registration Functionality

**CRITICAL FINDING**: The backend registration functionality for course enrollment is ALREADY FULLY IMPLEMENTED. The RegistrationService class already includes all requested functionality:

- RegisterStudent (for POST /api/self-service/register)
- DropCourse (for DELETE /api/self-service/register/{enrollmentId}) 
- RequestCourseSwapAsync (for POST /api/self-service/swap)
- GetSwapRequestsAsync (for GET /api/self-service/swap-requests)
- ProcessSwapRequestAsync (for PUT /api/self-service/swap-requests/{id}/approve)
- GetRegistrationHistoryAsync (for GET /api/self-service/registration-history)

This means the backend self-service/registration APIs are complete and ready for frontend consumption. The frontend work below focuses on creating the Angular UI to consume these existing APIs.

## Implementation Approach

1. **Create Services First** - Angular services that wrap the HTTP API calls
2. **Create Models** - TypeScript interfaces/models that match the backend DTOs
3. **Create Components** - Angular components for UI pages and reusable UI elements
4. **Setup Routing** - Add new routes to app.routes.ts
5. **Update Navigation** - Add menu items to relevant navigation components
6. **Add Styles** - CSS styling for new components

## Technical Details

### Service Pattern
Each service should:
- Inject HttpClient
- Handle error responses appropriately
- Return Observables of the appropriate model types
- Follow the existing service patterns in the codebase
- Include proper typing for request/response objects

### Component Pattern
Each component should:
- Use OnPush change detection where appropriate
- Implement proper unsubscribing to prevent memory leaks
- Follow Angular Material design patterns (assuming the project uses it)
- Include proper form validation
- Handle loading states and error states

### Model Pattern
Each model should:
- Match the backend DTO structure exactly
- Include proper type annotations
- Optionally include factory methods for creating instances from API responses
- Be placed in the models directory
